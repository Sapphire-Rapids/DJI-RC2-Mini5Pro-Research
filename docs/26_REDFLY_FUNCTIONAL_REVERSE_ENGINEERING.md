# RedFly 完整功能与实现分析

RedFly 有不少可借鉴的实现。对 FindUAS 最有价值的是进程内 SDK 接入、参数元数据与写后读回、带来源标记的遥测、GNSS 诊断、配置档案及离线地图。建议把这些设计重写成我们自己的源码模块，再为固定 Fly 版本做小型适配。现有 APK 可以作为本地实验基底，但目前没有可直接 fork 的源码工程，也没有证明它已实现 Mini 5 Pro 的完整标准 RID 关闭或广播字段编辑。

本报告对应用户提供的 installer245（A-104）及其内嵌 Fly236（A-105，包名 `dji.go.v6`，自报基于 Fly 1.21.10）。它补全此前 C-476--C-482 的安装器、RID、GPS、日志、参数编辑器和二开分析。详细记录、入口、默认值、调用链、确认与恢复边界见[功能证据索引](../evidence/redfly-full-functional-review.json)，逐项比较见[功能矩阵](../evidence/redfly-feature-matrix.csv)。

## 覆盖范围

全包 32 个 DEX 共含 176,976 个类定义；引用扫描遍历 1,063,288 个有方法体的方法，覆盖 37 个已识别的定制包根、813 个定制类定义，得到 113 处宿主到定制代码的引用。结合当前五页菜单、Manifest 启动入口、官网功能说明、外层安装器和定向原生分析，形成了本报告的功能清单。共整理 78 条记录。矩阵的每一行是可复查的功能或边界记录，也包括未接通的旧入口和宿主依赖，不是已通过实机验证的功能数量。

这些数字说明搜索范围，不是“所有功能已经运行”。反射、混淆或原生内部的其他修改仍不能由该引用图排除。主包是 ARMv7，已有官方同版样本是 ARM64，因此不能通过直接二进制 diff 认定每段代码都是 RedFly 新增。原有 Fly 的连接、FPV、相机、相册、地图、任务及设备设置作为宿主能力登记；本次没有重新审计每个官方算法或第三方库。内嵌 Utilities、installer 和 Files 沿用已有身份及调用分析，不把它们各自的通用功能冒充 RedFly 新增实现。

全部新增功能结论是 `STATIC`。未启动 APK、执行厂商代码、安装或重签软件、连接飞机/遥控器，也未调用包内的网络服务。能追到 SET、回调或读回代码，均不等于本次观察到设备接受。各功能对 RC2 / Mini 5 Pro 的实际支持、断电持久性与 RF 效果仍需各自验证。

## 关键实现与不能混淆的地方

### 同进程接入是共同基础

大多数控制从原 Fly 菜单、连接事件或按键路由进入定制类，再调用现成的 FlyModel、`UAVKeyManager`、`DataBase` 和 native SDK。参数编辑器的 `Wire` 复用 `ServiceManager` 的已有通信环境。它没有让普通外部 APK 自动获得同一套连接、缓存和回调。

这也是二开应采用“小模块加宿主适配”的原因：我们可以维护自己的 UI、状态机、证据日志和协议适配，而不必重建整个反编译 Fly。个别 RC2 兼容动作另走本机桥，确认语义更弱，不能与原 SDK 路径混为一谈。

### RID、GPS、地区和上报是不同控制面

RID Kill 默认开启。除云控拦截外，它在连接后反复发送 legacy DroneID mask 和 EID 请求。前后 mask GET 只记录，不保存或核对原值；没有 EID 独立读回；关闭设置或断连也没有恢复原状态。这与[官网](https://redfly.app/?lang=en)“不能完全关闭 DroneID/RID”的说明一致。

遥控器 GPS 改 Android `location_mode`；飞机 GPS 改 `FCGPSEnabled`。FCC/地区改无线电相关请求，UTMiSS 改应用侧网络上报授权。它们均不能替代标准 RID 开关、Basic/UAS ID、飞机位置或操作者位置的独立控制与 RF 验收。无登录路径还会将一个固定合成 UUID 送入已有同步链，它不是任意身份编辑器。

LTE 还修改了原有地区判断：部分可用性函数直接返回 true，两端的地区不支持检查则直接返回 false。设置页继续经过剩余硬件、网络、绑定和服务条件，再请求 HYBRID；另一项 Wi-Fi 地区判断仍在。这与自动 HYBRID 的定时请求是两件事，不能从“地区检查放开”推出所有地区门禁消失，或硬件、订阅及实际 4G 链路已经可用。

Developer Mode Tools 的入口被显示出来。Phone UUID 是应用本地生成并保存的随机 UUID；Aircraft FCUID 所显示的来源是 SDK `KeyProductUUID` 的当前值/监听，并非主动硬件 GET。两者都应与无登录同步用的账户 UID、Android ID 和操作者注册号分开。该页还提供复制和手动扫码诊断提交，接受的扫码 URL 会收到设备型号、序列号等字段；打开页面本身不触发提交，本次没有读取实际标识或扫码联网。

### 参数编辑器最接近可借鉴的控制闭环

`verifiedWrite` 在写前重新核对设备元数据和预期当前值，经 E3 写入后再发 E2 读值比较。这个独立读值步骤比只看回调或本地缓存更有参考价值。

仍需重写的部分很具体：可写属性被固定为 1；备份取内存快照，可能混入旧连接数据；恢复按名称和类型匹配，不强制绑定备份的原飞机；批量中途失败不会回滚已经成功的项；取消页面任务不保证在途请求结束。每次控制都应持久记录原值、会话、已发送/已确认/结果未知和恢复结果。

### GNSS 与遥测并非全部被动

遥测目录含 5,200 个条目，其中 3,599 个 SDK 项、1,601 个 push getter，另加两个本地派生值。它有来源/错误/缓存年龄分类；“读取全部”先取缓存，再对符合条件的空项发主动读取。该目录的名称、类型与枚举不能证明 Mini 5 Pro 支持。

GNSS 实验室打开页面时会请求 `GPSSNRInfoPushEnable=true`。本地 HTTP 的 `/start` 单独启动收集时则不自动开启 SNR/raw。手动的 SNR/raw 开关用 SDK 缓存判断先前值，先标记“由自己开启”，随后才发送 SET；结束时对这些标记发送 false，没有可靠地还原未知原值，清理写入也未持续绑定原飞机。

遥测高级编辑器主要修改倍率、精度、标签与字段路径，但其 `Request update` 按钮会直接调用五种受支持的请求之一，没有额外确认。GPS SNR 请求会启用推送，检查结果时又可能读到已有缓存包。应将这类动作明确列为控制，而不是包装成刷新显示。

飞机 SNR 图使用数组槽位，`S1` 等是本地编号；数值经过位处理，不能直接当真实卫星身份或已经核实的 dB-Hz。干扰/欺骗状态来自 SDK 或 Home push 的位段解释，保留了原状态码，但未做真实干扰实验。它可以成为诊断界面，不能仅凭“OK”证明定位可信。

### 飞控快捷动作的保证程度不同

Smart RTH 设置有 SET 后 GET，主降落保护设置还交叉检查参数；云台校准区分请求 ACK、进度与完成，停止也等待状态确认。这些设计可参考。

相比之下，档位 Mapping 的三次写入不是事务，恢复依赖本地偏好；部分 LED/GPS 的 rc331 兼容桥不等待 ACK；自定义按键在原动作条件拦截之前执行，并立即返回 completed。飞机关机只确认请求已提交。它们不能共用一个“成功”标记。

高度功能只是让原界面保留设备范围，跳过 CE 120m 裁剪；当前新菜单未接通旧 `tabAdvanced` 的高度开关。Waypoint Lite 只合并/简化地图线条、标记和文字。声明的高度/距离复刻 helper 则未找到直接 attach/detach 接线。矩阵保留这些可达性差异，没有把旧代码存在当作当前用户可用功能。

### 文件、画面和地图的边界

遥测 Profile 保存显示行、收藏、轮询间隔、monitor 和布局，不包含实时读数，也不是全部 mod 设置的备份。导入有大小、格式、版本及字段校验，提供 Add/Replace/Cancel，并保存一份可撤销的旧配置；应用过程跨多个偏好文件，不是原子事务。菜单包装层支持 19 种语言，地图模块则只在 en/ru 间选择，两者不能混同。

直播服务绑定 `0.0.0.0:8080`，使用明文 HTTP，没有鉴权。状态接口会包含热点凭据，遥测接口包含位置。Ready 取自热点就绪；直播对话框关闭不停止服务，遥测订阅也没有完整释放，值缺少年龄标记。可参考编码器接入和有限队列，接入产品前应重建服务生命周期及访问控制。

地图切换复用 Mapbox。离线下载采用 zoom 6--18，tile 上限 300,000；数据库迁移与模型 ZIP 是两条不同流程，ZIP 有路径、大小、SHA-256 和 stage/backup 激活检查，数据库复制分支则没有等价的完整性/原子替换保证。资源下载虽然有有限重试，但业务错误仍可能转默认包并标成 SUCCESS，不能只看最终状态文案。

飞行记录导出得到的是 UIMap/轨迹 JSON；已有输出会被跳过，DAT 后缀出现在扫描里也不证明 DAT 能解析。原生 `_sand` 是另一条日志：已追到 `JNI_SDKInitialize → initialize → InitializeLog → InitializeUAVLog`，其 formatter 保留 8 字节记录头、直接复制文本，写线程直接落盘。这个结果不提供历史加密日志或固件的解密方法。

### 默认行为值得单独记录

| 设置或动作 | 当前样本的默认/触发行为 |
| --- | --- |
| RID Kill、Force FCC | 默认开启，连接后相关路径可自动运行 |
| 应用/固件/FlySafe 更新拦截 | 三项默认开启；范围是选定入口，不是清空已有数据库或禁止所有 OTA |
| Java 日志加密 `enc_logs` | 默认关闭，仅影响已查的七个调用点；不覆盖所有日志，也不等同原生 SandPlain |
| 遥测 monitor | 默认开启，实际由收藏/选中项驱动；画面读数另有自己的开关 |
| 新自定义读数 | 五个初始行均未启用；不等于后台 monitor 也关闭 |
| 自动 HYBRID | 默认关闭；开启后提交请求，不等待实际切换确认 |
| 启动诊断上报 | 默认开启；HTTPS POST 到 RedFly 的 challenge/launch 服务，含版本、安装随机 ID、设备型号/固件等 |
| Probe42 | 随启动/UUID hook 自动记录本地缓存，未见 UI 关闭开关 |

启动诊断所查载荷没有构造坐标、设备序列号、账号或飞行记录字段；这只限定该路径，不能代表整包所有 SDK 的网络行为。它使用 Base64 和工作量证明，传输保护依靠 HTTPS。录屏保护另有一个具体配置不一致：宿主调用的无参 getter 读取 `v5` 路径，而新菜单写当前 `v6` 配置，因此该 UI 开关到实际效果尚未闭合。

## 如何用于 FindUAS 与二次开发

推荐先实现我们自己的进程内诊断模块，固定宿主摘要和版本，证明它能使用现有连接并正确区分缓存、主动读取和监听。随后选一个已识别且可恢复的控制，完成原值记录、一次变化、独立读回、恢复和恢复读回。原 RID 面板目标还需要每个字段自己的 owner 和独立 RF 证据。

| 优先级 | 建议借鉴 | 必须重写的部分 |
| --- | --- | --- |
| 第一批 | 参数元数据/写前值核对/独立读回；少量已知遥测键；带来源的 GNSS 记录 | 身份和连接代次、结果未知、持久原值日志、清理与恢复 |
| 第二批 | 显示档案、日志导出、地图/资源归档、第二屏 | 凭据和数据访问、目录迁移、真实新鲜度、文件校验与发布 |
| 按研究需要 | 云台/降落/RTH 的状态机、按键和界面接入方法 | 保留宿主条件检查，明确设备门禁与每项确认语义 |
| 不直接沿用 | 默认 RID 周期写、盲发兼容桥、固定无登录身份、自动 root/force-stop、默认第三方诊断上报 | 从明确需求重新设计，不将其视为已经验证的设备能力 |

修改固定 APK 做小范围实验是可行的工程方向，但还没有实际重打包验证。原安装器固定检查作者签名、包身份和 payload 摘要，重签后不能假定继续通过；自己的安装和更新流程也要随模块一起建立。整个 Fly 反编译后全面重建会引入大量无关代码和还原错误，目前不推荐。

本轮完成的是功能与实现的静态盘点和复用判断。可复查资料保存在上述索引和矩阵，厂商 APK/DEX/SO、反编译源码与原始日志仍留在仓库外。它不改变原 RID 控制面板尚未完成实机与 RF 验收的状态。
